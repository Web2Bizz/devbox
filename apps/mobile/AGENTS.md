# AGENTS.md — opencode-mobile

Expo 57 + React Native 0.86.3 + React 19.2.3 + Expo Router. Single app, no monorepo. Entry `expo-router/entry`, screens in `app/` (file-based routing), business logic in `src/lib/`, Zustand stores in `src/stores/`.

> `.opencode/` is a separate git repo (the portable opencode pack). Its `AGENTS.md` describes pack internals — don't confuse with this file.

## Commands

```bash
npm install --legacy-peer-deps   # required — .npmrc sets legacy-peer-deps=true, peer constraints need it
npm run typecheck                # tsc --noEmit (strict, sole verification gate)
npm test                         # node --test 'src/**/*.test.ts' 'scripts/*.test.mjs' — needs Node >= 23.6 for TS type-stripping
node --test src/lib/auth.test.ts # single test file
npm run check:versions           # verifies package.json ↔ app.json ↔ android/app/build.gradle ↔ changelogs
node scripts/sync-version.mjs    # sync versionName from package.json → app.json + build.gradle
npx expo start --clear           # start with cache clear
npx expo run:android / run:ios   # dev build (needed for native modules)
```

No `lint`/`format` scripts despite `CONTRIBUTING.md` mentioning `npm run lint` — there is no ESLint/Prettier config; `typecheck` + `test` are the CI gates (`.github/workflows/build.yml`, `ios-ci.yml`).

## Version bump (single source: `package.json`)

1. Bump `version` in `package.json` only.
2. Bump `expo.android.versionCode` in `app.json` (integer, monotonic — Play/F-Droid key upgrades off it).
3. Run `node scripts/sync-version.mjs` — syncs `app.json` version + `android/app/build.gradle` versionName.
4. Create `distribution/changelogs/<versionCode>.txt` and `fastlane/metadata/android/en-US/changelogs/<versionCode>.txt` — first line must be `v<version>` (enforced by `check:versions`).
5. `npx expo prebuild --clean --platform android --no-install` if versionCode changed (prebuild regenerates native project).
6. Verify `npm run check:versions && npm run typecheck && npm test`.

`app.config.js` re-exports `version` from `package.json` at runtime so `Constants.expoConfig` is always correct, but `app.json` is still checked.

## Version auto-increment (CI, ported from web2bizz/ui)

`.github/workflows/bump-version.yml` runs on every push to `dev`/`main` (+ manual dispatch) and commits exactly one `chore: bump version … [skip bump]` on top:
- `dev` → `scripts/bump-version.mjs` carry-on-9 patch bump (same as web2bizz/ui: `0.4.19 → 0.5.0`).
- `main` (merges) → `scripts/bump-version.mjs --major`: major+1 with minor/patch reset (`0.4.15 → 1.0.0`).
- `scripts/bump-release-meta.mjs` then bumps `versionCode` +1 (monotonic across majors, never reset), re-runs `sync-version.mjs`, and creates stub changelogs for the new code — fill the stub body before release, never ship it.
- Manual: `npm run version:bump` / `version:bump:major` / `version:bump:dry`.

## Project structure

- `app/` — Expo Router screens. `_layout.tsx` is root (auth gate, SSE, notifications, telemetry consent). `(tabs)/` holds tab group, `session/[id].tsx`, `connection/`, `project/`.
- `src/lib/sdk.ts` — custom lightweight opencode client over `expo/fetch` (not generated `@opencode-ai/sdk`). All API calls go through here; SSE via `src/lib/sse.ts`.
- `src/lib/` — pure utils with colocated `*.test.ts`. Each module is independently testable.
- `packages/uikit/` — `@web2bizz/ui-native`: the SINGLE home for reusable UI (components, theme, tablet hook, UI-support utils in `src/utils/`). Never duplicate a component in `src/components/` — app-bound components (stores, server clients, release checks: `AuthGate`, `CloneRepoSheet`, `ConnectionBadge`, `UpdateBanner`, `ErrorBoundary`) live in `src/components/` instead. Utils moved here keep their colocated tests; `npm test` covers `packages/uikit/src/**/*.test.ts` too.
- `src/stores/` — Zustand stores (`auth`, `connections`, `events`, `catalog`, `settings`).
- `src/components/` — shared UI (`AuthGate`, `ErrorBoundary`, etc.).
- `scripts/*.mjs` — release/product scripts, each with `*.test.mjs` run by `npm test`.
- `android/` — generated by `expo prebuild`, not hand-edited (except signing). Don't edit directly; re-run prebuild.
- `tsconfig.json` — `strict: true`, path alias `@/*` → `./src/*` defined but codebase uses relative imports (`../lib/*`). Either works; match surrounding file.

## Gotchas

- `typecheck` excludes `**/*.test.ts` and `tests/fixtures/**` — tests can have looser types that `tsc` won't catch.
- Native modules (`expo-secure-store`, `expo-local-authentication`, notifications) don't work in Expo Go — need `expo run:android/ios` dev build.
- Legacy peer deps: `npm ci --legacy-peer-deps` in CI; plain `npm install` fails on peer conflicts (Expo 57 + RN 0.86 + React 19).
- Node version split: CI `test` job uses Node 24 (type-stripping), `build` job uses Node 20. Local Node 23.6+ required for `npm test` on `.ts` files.
- `distribution/` and `fastlane/metadata/` changelogs must exist per versionCode — missing file fails `check:versions` and blocks CI.
